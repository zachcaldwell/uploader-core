uploader-core GitHub

Shrink photos before they're uploaded.

A web component that compresses photos in the browser and uploads them straight to your own S3, R2 or Supabase bucket. Nothing in between to run or pay for.

Install from GitHub while it's in beta:

npm install github:zachcaldwell/uploader-core

Try it

Drop photos here or choose them from your device

Your photos never leave this browser: the demo's bucket is a service worker.

How a photo gets to your bucket

  1. The browser shrinks it

    Resized to fit, re-encoded, turned upright, with its location data stripped. Pica does the resizing in a worker, so the page stays responsive.

  2. Your server signs for it

    One small endpoint checks who's asking and returns a short-lived upload URL. presignS3 or presignSupabase writes it.

  3. The browser uploads it

    Straight to your bucket, with progress, retries and cancel. You store the key it hands back.

The code

In the page

<script type="module">
  import 'uploader-core/element';
  import 'uploader-core/element.css'; // optional
</script>

<photo-upload presign="/api/presign" multiple></photo-upload>

<script>
  document.querySelector('photo-upload')
    .addEventListener('complete', (e) => save(e.detail.key));
</script>

On the server

import { presignS3 } from 'uploader-core/server';

export async function POST({ request }) {
  // Check who's asking first: the endpoint is yours.
  return Response.json(
    await presignS3(r2, {
      key: `uploads/${crypto.randomUUID()}`,
      request: await request.json(),
      maxBytes: 5_000_000
    })
  );
}

Or with your own interface

import { compress, upload } from 'uploader-core';

const small = await compress(file, { maxWidth: 2048, maxHeight: 2048, format: 'webp' });
const { key } = await upload(small, { presign: '/api/presign', onProgress: (p) => (progress = p) });

What it takes care of

Sideways phone photos
Turned upright from their EXIF orientation before they're resized.
Location data
Re-encoding drops EXIF, GPS included, so you don't store where people live.
Files that are already small
Passed through untouched when re-encoding wouldn't make them smaller.
Transparency
PNGs stay PNGs, alpha channel and all, unless you ask for another format.
Flaky connections
A dropped connection or a server error is retried with backoff; a refusal isn't.
Your styles
No shadow DOM and no classes of its own: style its parts with Tailwind, plain CSS or anything else, or use the default look.
